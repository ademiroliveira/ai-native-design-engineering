# Product & UX Framing

Use this skill before implementation when the request is ambiguous or outcome-driven.

## Process

1. Identify the user, context, problem, and desired outcome.
2. State assumptions and unknowns.
3. Define the primary flow and meaningful alternate or error paths.
4. Define acceptance criteria and key interaction states.
5. Surface open questions instead of silently inventing product behaviour.

## Output

Problem framing → assumptions → flow → states → acceptance criteria → open questions.
