# Accessibility & Responsive UI

Treat accessibility and responsiveness as product requirements.

Check semantic structure, accessible names and labels, keyboard navigation, focus visibility, contrast, reduced motion where relevant, touch targets, and layout behaviour across viewport sizes.

Infer responsive rules rather than scaling desktop layouts mechanically. Identify content priority, layout transitions, component behaviour, and navigation changes at relevant breakpoints.

Prefer progressive enhancement and repository conventions over ad hoc fixes. Verify with available tools and clearly state anything that could not be checked.
